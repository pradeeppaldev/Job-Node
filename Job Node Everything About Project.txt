**Data Flow / Typical User Scenarios (step-by-step)**
- Register/login:
  - Frontend sends credentials to `/api/users/register` or `/api/users/login` → Controller validates, creates user, responds with a token (via `generateToken`) → Frontend stores token (localStorage or context) and sets auth headers for future requests.
- Post a job (recruiter):
  - Recruiter fills `AddJob` form → file(s) uploaded via `multer` → image uploaded to Cloudinary → controller creates `Job` document in DB → response returns job details.
- Apply to job (candidate):
  - Candidate views `JobListing` → clicks apply → frontend posts application data to `/api/jobs/:id/apply` → controller saves `jobApplications` entry and links to `Job`/`User`.
- Manage applications:
  - Recruiter accesses `ManageJob` / `ViewApplications` → controller queries `jobApplications` collection, returns list for UI to display.

**Interview Q&A (common questions + concise answers)**
- Q: What is the project and its purpose?  
  A: A job board for recruiters and candidates to post/manage jobs and applications; full-stack app demonstrating real-world CRUD, auth, file uploads, and deployment.
- Q: Which technologies did you use and why?  
  A: React (fast SPA dev with Vite), Tailwind (rapid styling), Node/Express (lightweight API), MongoDB (flexible schema for jobs/applications), Cloudinary (reliable media storage).
- Q: How does authentication work?  
  A: Server issues JWTs via `generateToken`; `authMiddleware` validates tokens on protected routes; tokens stored by client for authorized requests.
- Q: How are file uploads handled?  
  A: `multer` parses multipart/form-data; files forwarded to Cloudinary via cloudinary.js; controllers store resulting URLs in DB.
- Q: How do you secure private endpoints?  
  A: Use `authMiddleware` to check JWT and optionally role checks for recruiter-specific actions; validate inputs and sanitize data.
- Q: Explain one challenging bug you fixed (prep an example from code).  
  A: Pick a real bug you solved (e.g., CORS issues, token expiry handling) and explain root cause → fix → result.
- Q: How would you scale this app?  
  A: Move to microservices for heavy features, use connection pooling, horizontal scaling behind a load balancer, use Redis for caching, and paginate DB queries.
- Q: How is data modeled for jobs and applications?  
  A: `Job` documents store details + reference to `Company` or `User`; `jobApplications` store applicant info linked to `Job` and `User`.
- Q: How would you add tests?  
  A: Add unit tests for controllers and utils (Jest), integration tests for routes (supertest), and E2E tests for frontend (Cypress).
- Q: How do you handle errors?  
  A: Centralize error responses in controllers and middleware (catch async errors, return consistent status codes and messages).

**Security & Production Notes**
- Validate and sanitize all inputs server-side.  
- Store JWTs securely (httpOnly cookie preferred over localStorage for XSS resistance).  
- Enforce rate-limiting on auth endpoints.  
- Use HTTPS, secure Cloudinary keys in env, rotate secrets.  
- Implement pagination and limit query sizes to avoid large DB scans.

**Common troubleshooting tips**
- If server fails to connect to DB: verify `MONGO_URI` and network access.  
- If uploads fail: check Cloudinary credentials in env and verify `multer` buffer handling.  
- CORS errors: ensure correct CORS middleware and allowed origins in server.js.  
- Token issues: check token expiry, signing secret consistency (`JWT_SECRET`).
